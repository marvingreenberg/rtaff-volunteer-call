# Task - separate out simplified volunteer call.

In a separate directory, ~/git/rtaff-voluteer-call create a standalone
app (backend and frontend) following the basic architecture of the whole rtaff-workflow - a python backend and a svelte frontend.

The app should use a "database" of volunteers.

Certain statistics should be maintainable for the volunteers (last assignment, assignment rate...) that will evolve over time.  The total number of volunteers will be under 1000

The functionality in the existing app should be maintained, but the existing schema may not be appropriate.  Now the volunteer call will be generated by data entered directly, consisting of a list of information like:

[ {short_description, date, time_range, full address, team_lead_email}, ... ]

When that data is entered through an "administrator" UI (roles, and similar login approach as in existing system, and the single database will contain the administrators/leads/volunteers who can all volunteer) the administrator now has the ability to "send" a volunteer call.

The team assignment tasks, possibiliy updating or setting the team lead, and similar actions should be possible. When the whole "call" has had volunteers assigned, the notify-volunteers action sent out, to the assigned voliunteers.

Consider approaches for the sending of the notification.  For email, what cloud-based services might
be integrated (constant-contact, google groups, etc) to allow self management of the
volunteer subscription?  Are there any issues for spam detection (e.g. large TO: lists,
 unrecognized FROM:). Consider adding an sms notification that sends a full notification, or just the link to check with somne brief summary.

Also consider having management in the application to allow a user to withdraw from subscribing,
pause subscribing (e.g., from May 1-July 1, for a month), and to allow delivery through sms/text
which would require adding a phone to the database - which should happen anyway (with an update
phone number with confirmation sms text).

Make sure this supports a mobile only for all tasks, but likely the creation/assignment will often be desktop.

Let's plan that all out, discuss any issues.  The new directory ~/git/rtaff-volunteer-call should
be a complete project.  Review the existing code in ~/git/rtaff.  Write a USE_CASES.md describing the proesses here.  Lets ignore maintaining the volunteer info data for now, but have an architectural stub to allow connecting to some existing data source (sharepoint list 🙄, external database) with a mapping to the required schema.
